Elf*/SElf* implementation and input-fidelity audit — 2026-11-04

Finding
Both benchmark entries are local C++ ports of the authors' Java implementations,
not calls into the official implementation. SElf* additionally serializes custom
cross-window checkpoints. Elf* has an extra 8-byte count header per block. Both
use a counted external block directory. The erasure guard is a local extension.

Reference
Unmodified https://github.com/Spatio-Temporal-Lab/SElfStar
commit 457ceb0033e98d516fef42e39d17c9d4b8abbfdb.
Java 8 Corretto 1.8.0_432. Existing compiled official compressor classes plus
original decoder sources, dsiutils 2.7.0 and fastutil 8.5.6.

Experiment
First 10,000 values from each of the 16 benchmark datasets; all 6,782 BP values.
156,782 values per conversion variant. Dataset prefix bytes are in samples.zip.
Converted each raw integer using both division by 10^decimals and multiplication
by its rounded reciprocal; wrote exact binary64 bits and supplied identical bits
to Java and C++. Used 1,000-value blocks, carrying original SElf refresh state.
Compared complete native payload bytes after stripping our headers/checkpoints.
All 628 per-block payload comparisons matched exactly. Both original Java
compressor/decompressor pairs round-tripped every tested value bit-for-bit.
This is sample-based fidelity evidence, not exhaustive full-dataset equivalence.

Root cause of inflated sampled compression results
benchmark_common.hpp:55-66 converts integer inputs to doubles in the main
translation unit, whose flags include -ffast-math (CMakeLists.txt:91).
A remote probe invoking that exact conversion method, compiled using GCC 13.4,
-O3 -march=native -mfpmath=sse -ffast-math -funroll-loops -flto=auto -std=gnu++23,
matched reciprocal multiplication on every sample and differed from strict
division on every dataset. See remote-conversion-check.json and manifest.json.
The compiler's reciprocal optimization changes many values by one ULP, which
breaks their short decimal representation and defeats erasure. The strict flags
on the codec translation unit do not repair already altered input values.

The reciprocal-mode totals exactly reproduce the saved benchmark compressed

183,992 and 189,088 bits. This confirms relevance to the recorded results.

Status and necessary follow-up
No benchmark source or existing result files were changed by this audit.
Current results/plots for codecs consuming the converted binary64 input must be
considered provisional. Correct the shared input conversion using strict IEEE
arithmetic, verify exact input bits under production compiler/linker flags, and
rerun every affected codec. Integer-input codecs are outside this conversion
path. Merely replacing the ports with Java would preserve this input problem.
The ports' performance remains performance of our C++ implementations, even
where compressed payloads match the original Java implementation.
