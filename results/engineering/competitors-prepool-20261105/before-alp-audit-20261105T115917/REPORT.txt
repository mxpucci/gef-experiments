Preliminary competitor comparison against native GEF 942d3c4

Scope: all 25 non-GEF codecs on the same 14 full datasets: AP, BM, BP, BT,
BW, CT, DP, DU, ECG, GE, LAT, LON, UK, WD. US and IT are excluded from ALL
aggregates because they were not complete in the captured results snapshot.
350 competitor rows + 28 GEF rows. No partial-input measurements.

GEF source: 942d3c4e063380425a290cb5dcc89466d95a3a78, uniform K=32000,
RLE_GEF and B_STAR_GEF_APPROXIMATE only. No pooling or GCD normalization.
GEF medians are the saved median-of-three rows from full16-final-r1.
Competitors: non-gef-20261105T021920Z, one standard suite measurement per case,
CPU 8 on the same host. Competitor block size 1000 where applicable; native
Fauna/Pcodec layouts retained. These are different layouts, not a matched-K
ablation. Input value counts are checked against GEF for each dataset.

pareto-arithmetic.pdf/png/svg follows the repository's equal-dataset arithmetic
averaging convention. pareto-geometric uses equal-dataset geometric means.
All 27 points use identical dataset coverage. The size axis is compressed /
original bytes, so lower is better; throughput axes are higher-is-better.
MiB/s is the actual 2^20 denominator used by the suite's fields named mbs.
Point-access speed is 1000 / ns per query in million values/s, computed BEFORE
averaging. Therefore the arithmetic average speed is not the inverse of the
arithmetic average latency. Both columns are preserved in the summary tables.
The corpus_ratio_pct column separately reports input-size-weighted storage.
Per-dataset plots are in the 14-page pareto-per-dataset.pdf.

Fairness limits:
* Timing harnesses differ. GefTuning uses an untimed whole-code warmup, a
  dedicated access warmup, three timed repeats and an ordinary checksum
  accumulator. LosslessBenchmarkFull uses each codec's existing timing and
  query-count policies; many legacy access loops use volatile accumulators.
  RNG implementations also differ (mt19937_64 vs mt19937). These differences
  can affect access rankings, especially the fastest implementations. These
  are preliminary comparisons, not controlled cross-codec speedup claims.
* GEF decodes into a preallocated buffer; competitor timing/allocation scopes
  are their existing suite implementations. Input conversion is outside the
  GEF integer representation comparison; floating codecs use suite conversion
  policies. No throughput is adjusted to compensate for these differences.
* Compression uses reported compressed bits/bytes, matching the repo plots.
  Total owned memory is unavailable for many competitors, so this is not a
  resident-memory comparison. Available owned_bytes are retained in the data.
* BUFF is precision_bounded. Fauna and MacaqueV use float32 conversion.
  These are hollow markers and excluded from the dashed frontier. Original
  validation_status/input_conversion fields are preserved. 'not_checked'
  on legacy rows is not promoted to a roundtrip validation guarantee.
* No uncertainty intervals are available for single-run competitors. Small
  gaps should not be interpreted as significant. Arithmetic and geometric
  averages can reverse close rankings; inspect per-dataset pages.

Observed aggregate trade-offs (both averaging conventions):
Both GEF variants lie on the compression/access Pareto frontiers. B*-GEF is
also on the decompression frontier; RLE-GEF is dominated there by B*-GEF.
LeCo/DAC have faster access than GEF but larger reported sizes. ALP leads
compression/decompression throughput at larger sizes. Pcodec int64 has the
smallest aggregate reported size and much slower point access. B*-GEF versus
NeaTS access is close and changes ordering with the averaging convention;
there is no defensible decisive winner from these harnesses.

Reproduction: run compare.py using Python with pandas/numpy/matplotlib.
The script imports only style definitions from ../../../scripts/pareto_plots.py.
Frozen source CSV hashes and exact frontier memberships are in manifest.json.
