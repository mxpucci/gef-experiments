BUFF and LeCo native access / provenance correction (2026-11-04)

BUFF
Paper: https://www.vldb.org/pvldb/vol14/p2586-liu.pdf
Source: https://github.com/Tranway1/buff
Pinned commit d6550b25a247e34b0dd88079b05e1ce83905630f (MIT, included LICENSE).

The previous buff-ffi crate adapted the codec and implemented its own point
extractor. It was not verbatim upstream code despite its old opening comment.
The replacement compiles original scalar byte_fixed_encode, byte_fixed_decode,
and buff_decode_condition method bodies, with their original precision/bitpack
helpers. tools/import_buff_upstream.py extracts them reproducibly from the
pinned submodule; upstream-items.json records original item hashes. This is a
small extracted codec crate, not a build of the authors' entire database app.
Unrelated RocksDB/Parquet/Tokio infrastructure is excluded.

The original scalar format supports indexed selective decoding. We now encode
one complete dataset column and use the authors' selective method for both point
and range queries; the generic -b 1000 does not affect BUFF. The column header
contains a u32 count; current datasets fit that limit. Our counted FFI header
adds 16 bytes (value count and decimal scale).

Explicit adaptations:
- Thin borrowed Segment and byte views at the C ABI; encoding reads the caller's
  input slice directly, and decoding borrows compressed
  storage instead of copying an entire Vec for every query.
- Disable original diagnostic print/info macros during timing.
- (2026-11-09) No codec patches. The earlier selective-decoder trailing-bit
  fix was dropped under the policy of patching only bugs that crash or change
  aggregate size/throughput (see "2026-11-09 upstream bug audit" below).
- Boundary validation and panic-to-error handling in FFI. Original encoder
  assumptions are not replaced by a different compression algorithm.

BUFF preserves the authors' bounded decimal precision; it is NOT bitwise
lossless binary64 compression. Metrics explicitly report precision_bounded and
count input/output bit mismatches. Out-of-bound or query errors produce warnings
and qualified metrics. This qualification must remain visible in comparisons.

2026-11-05 variant audit
The above encoder corresponds to the authors' plain scalar `buff` profiler
route. Their separate `buff-major` outlier/majority route is not integrated.
An isolated original-code comparison found material savings on some datasets,
including 19.38% on full BW, with identical decoded bounded-precision values.
See benchmark_results/20261105-competitor-audit/REPORT.txt. Its different storage
format requires matching native query handling before it can replace this entry.

2026-11-09 upstream bug audit
Known upstream bugs in the extracted plain BUFF code, left unpatched:
1. byte_fixed_encode min/max uses `if fixed<min {..} else if fixed>max {..}`,
   so the first value can never set max ([10,5,7,6] @ scale 10 -> [6,5,5,6]).
2. Width `(delta as f64).log2().ceil()` is one bit short when delta is a power
   of two ([1,2,3,17] -> [1,2,3,1]).
3. `fixed_len - dec_len` underflows for narrow ranges (delta < 2^dec_len); in
   release builds the header width exceeds 64 and the FFI rejects the column.
4. PRECISION_MAP maps 13..=15 decimals to 10 fractional bits (~1e-3 error).
5. buff_decode_condition shifts the trailing `remain` low bits left by
   `remain`, so point/range reads disagree with full decode whenever the
   total width is not a multiple of 8.
Measured on all 16 full datasets (Linux x86, release build): bugs 1-4 never
trigger (decimals 1..9; payloads byte-identical with or without fixes 1-3;
full decode within the precision bound and exact after rounding to the
declared decimals). Bug 5 leaves sizes unchanged and causes no crash, but
point reads mismatch on 14/16 datasets (all but BM and IT, whose widths are
24 and 16 bits); the harness warns and keeps metrics. The May 2026 adapter on
main fixed 1-3; equivalent patches are not applied here because none changes
aggregate metrics on these datasets.
